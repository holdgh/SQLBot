# 二、几个关键设计我认为非常正确

## 1. Metric + Schema双层语义设计

你方案：

```
Metric
    ↓
Schema
    ↓
SQL
```

非常正确。

因为：

Schema解决：

> 数据在哪里？

Metric解决：

> 业务应该查什么？

例如：

用户：

> 五一上海游客量

Metric：

```
游客量
=
sum(visitor_count)
```

Schema：

```
tourism_flow.visitor_count
```

如果没有Metric：

Schema检索很容易得到：

```
visitor_num
visitor_count
visitor_people
```

但是不知道哪个是业务口径。

# 问题5：计算引擎定位还可以再明确

你的设计：

```
plan.calculation
```

控制计算。

正确。

但是建议：

不要把所有计算都放Python。

分三类：

---

## 类型1：数据库计算

例如：

```
sum
count
avg
group by
```

放SQL。

---

## 类型2：业务公式

例如：

同比：

```
(current-last)/last
```

放计算引擎。

---

## 类型3：统计分析

例如：

趋势拟合

预测

异常检测

以后再扩。

---

所以：

计算引擎应该定义：

```
Post Query Calculation Engine
```

而不是：

所有计算中心。
