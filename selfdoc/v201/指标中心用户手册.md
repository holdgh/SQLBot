## 1. 功能概述

指标中心是 SQLBot 问数链路的**业务口径权威来源**，解决"查什么"的问题。它由三部分组成：

| 组成 | 说明 |
| -- | -- |
| **指标库** | 录入业务指标（名称、口径定义、聚合方式、来源表字段、所属数据源、类型、单位、维度等），问数时按 BM25 + 向量混合召回注入 LLM 提示词 |
| **维度库** | 录入分析维度（名称、默认字段、别名），指标通过"支持维度"关联维度 |
| **管理页面** | 前端 `/set/metric` 页面，提供指标与维度的增删改查、启停 |

核心设计原则（验证时可对照）：

- **开关默认关**：`METRIC_CENTER_ENABLED=false` 时，问数链路与原版完全一致（不召回、不写日志、提示词无变化）；但管理页 CRUD 不受开关影响，始终可用。
- **数据源隔离**：指标可限定生效数据源（`specific_ds` + `datasource_ids`），召回时按当前问数的数据源过滤。
- **元数据与检索索引分离**：改口径只改指标定义，系统自动重建检索文档与向量，不产生双写。
- **每次编辑版本号 +1**：`version` 字段自增，便于追溯历史口径。

## 2. 功能入口与权限

### 2.1 页面入口

- **路径**：浏览器访问 `/set/metric`（如 `http://<host>/set/metric`）。
- **菜单入口**：顶部「设置」→ 子菜单「指标管理」。
  - 注意：顶层左侧菜单**不应**出现「指标管理」入口（问题 1 已修复：`Menu.vue` 排除列表加了 `metric`，只保留设置子菜单入口）——验证时请确认顶层菜单没有重复入口。
- **权限门槛**：前端 `/set/*` 路由仅**空间管理员（isSpaceAdmin）**可见；后端全部接口要求 `ws_admin` 角色（`weight != 0` 或超管）。普通用户访问 `/set/metric` 会被重定向。

### 2.2 后端接口一览（前缀 `/api/v1/system/metric`）

| 方法 | 路径 | 作用 |
| -- | -- | -- |
| GET | `/page/{current}/{size}?name=&ds_list=` | 指标分页查询 |
| PUT | ``（空路径） | 新建或更新指标（有 id=更新，无 id=新建） |
| DELETE | ``（body: id_list） | 批量删除指标 |
| GET | `/{id}/enable/{true\|false}` | 启停指标 |
| GET | `/dimension/list?name=` | 维度全量列表 |
| PUT | `/dimension` | 新建或更新维度 |
| DELETE | `/dimension`（body: id_list） | 删除维度 |

所有接口都有系统审计日志（模块 `metric`）。

## 3. 开关与配置

### 3.1 功能开关

配置项定义在 **`backend/common/core/config.py`** 的 `Settings` 类中（`【改造标记 METRIC-CENTER】` 配置段，L151-155），默认值即代码中写死的值：

```python
# ========= 【改造标记 METRIC-CENTER】↓ 指标中心配置（Phase 1） =========
METRIC_CENTER_ENABLED: bool = False   # 默认关=与原版行为完全一致
EMBEDDING_METRIC_SIMILARITY: float = EMBEDDING_DEFAULT_SIMILARITY   # = 0.4
EMBEDDING_METRIC_TOP_COUNT: int = EMBEDDING_DEFAULT_TOP_COUNT       # = 5
# ========= 【改造标记 METRIC-CENTER】↑ 指标中心配置结束 =========
```

开启方式（三选一，按 pydantic-settings 优先级从高到低）：

1. **环境变量**：`METRIC_CENTER_ENABLED=true`（进程环境变量，优先级最高；`METRIC_CENTER_ENABLED` 已加入 `lowercase_bool` 校验器 L161，支持字符串 "true"/"false"）；
2. **`.env` 文件**：`config.py` 的 `SettingsConfigDict` 配置了 `env_file="../.env"`（即项目根目录 `.env`）——**注意：当前项目根目录并不存在 `.env` 文件**，此路径仅为 pydantic-settings 的预留机制，若创建该文件则其中的值会覆盖 config.py 默认值；
3. **直接修改 `config.py` 默认值**（当前项目实际生效的来源——无环境变量、无 `.env` 时，运行值 = config.py 中的代码默认值）。

修改后需**重启后端服务**生效：

```bash
# 开启指标中心（问数链路生效）
METRIC_CENTER_ENABLED=true

# 关闭（默认）= 与原版 SQLBot 行为完全一致
METRIC_CENTER_ENABLED=false
```

开关行为对照：

| 开关状态 | 管理页 CRUD | 问数召回 | FILTER_METRICS 日志 | 提示词指标块 |
| -- | -- | -- | -- | -- |
| `true` | 可用 | 执行 | 有 | 有（命中时） |
| `false`（默认） | 可用 | 不执行 | 无 | 无（逐字一致） |

指标库为空时，即使开关开，召回也为空——提示词同样无指标块。

### 3.2 检索相关配置（一般用默认值即可）

以下配置同样定义在 `backend/common/core/config.py`（分别位于基础段、`【改造标记 RAG-KEYWORD】` 段 L137-144、`【改造标记 LLM-CONTEXT-FILTER】` 段 L146-149），代码默认值如下：

```python
EMBEDDING_ENABLED = True                      # 向量检索总开关（须开，否则只剩 BM25）
KEYWORD_RETRIEVAL_ENABLED = True              # BM25 关键词检索开关
KEYWORD_RETRIEVAL_TOP_COUNT = 10              # BM25 返回条数
KEYWORD_RETRIEVAL_MAX_CANDIDATES = 2000       # BM25 打分前候选集上限
LLM_CONTEXT_FILTER_ENABLED = True             # LLM 二次过滤开关
LLM_CONTEXT_FILTER_MIN_CANDIDATES = 3         # 候选总数低于此值跳过二次过滤
EMBEDDING_METRIC_SIMILARITY = 0.4             # 指标向量召回相似度阈值（METRIC-CENTER 段）
EMBEDDING_METRIC_TOP_COUNT = 5                # 指标向量召回条数上限（METRIC-CENTER 段）
```

## 4. 指标管理页——指标 Tab

进入 `/set/metric` 后默认显示「指标」tab。

### 4.1 列表功能

**工具行**：

- **搜索框**：输入关键字，回车触发；按指标名称模糊匹配（后端 `ILIKE %name%`）。
- **筛选按钮**：打开筛选抽屉，当前唯一筛选项为「数据源」多选。筛选逻辑：选中数据源 ds 后，显示"所有数据源生效的指标" + "限定在所选数据源上的指标"。
- **新建指标按钮**：打开新建抽屉。

**列表列**：

| 列 | 内容说明 |
| -- | -- |
| 多选框 | 批量删除用，跨页保留选择 |
| 指标名称 | 指标名 +（别名1,别名2）后缀 |
| 指标类型 | 原子指标 / 派生指标 / 复合指标 |
| 指标定义 | description，3 行截断，悬停看全文 |
| 聚合方式 | sum/avg/count/min/max |
| 单位 | 元/人/次/% 等 |
| 生效数据源 | "所有数据源" 或具体数据源名列表 |
| 状态 | 启停 switch，点击即时生效 |
| 创建时间 | 可排序，格式 YYYY-MM-DD HH:mm:ss |
| 操作 | 编辑 / 删除 |

**行交互**：

- 点击行空白处 → 打开「指标详情」抽屉（只读）。
- 状态 switch 切换 → 调启用/停用接口，提示"保存成功"并刷新。停用后该指标**不再参与问数召回**。
- 删除 → 二次确认"是否删除指标：xxx？"→ 级联删除其别名、检索文档、维度关系、依赖关系。
- 批量删除 → 底栏显示"已选 N 条"，确认后按 id 列表删除。
- 分页：每页 10/20/30 条可选，默认 10，按创建时间倒序。

### 4.2 新建/编辑表单（字段详解）

点击「新建指标」或行操作「编辑」打开 680px 宽抽屉。**必填项仅两个：指标名称、指标定义（描述）**，其余选填。

| # | 字段 | 控件与规则 | 说明 |
| -- | -- | -- | -- |
| 1 | 指标名称 | 文本框，必填，最长 100 | oid + 数据源作用域内唯一，重复保存报"该指标在当前作用域已存在" |
| 2 | 指标定义 | 多行文本，必填 | 口径的文字描述，会写入检索文档，召回后注入提示词 |
| 3 | 业务域 | 文本框，选填 | 如"交易"、"营销" |
| 4 | 指标类型 | 下拉，固定 3 项，默认原子指标 | 原子指标 atomic / 派生指标 derived / 复合指标 composite |
| 5 | 可加性 | 下拉，固定 3 项，默认可加 | 可加 additive / 半可加 semi / 不可加 non（为 Phase 3 结果校验 L3 预留） |
| 6 | 聚合方式 | 可搜索下拉（允许手输），可清空 | 固定候选：sum/avg/count/min/max；允许手输以兼容存量值 |
| 7 | 单位 | 文本框 | 如元/人/次/% |
| 8 | 表所属数据源 | 可搜索下拉，可清空 | **级联起点**（073 新增字段 source_ds_id）；选项来自数据源列表 |
| 9 | 来源表 | 可搜索下拉，**允许手输**，未选数据源时禁用 | 候选来自所选数据源的已同步表清单；占位提示"请先选择表所属数据源" |
| 10 | 来源字段 | 可搜索下拉，**允许手输**，未选表时禁用 | 候选来自所选表的字段清单；占位"请先选择来源表" |
| 11 | 时间字段 | 同"来源字段" | 候选一致；用于标注指标的时间口径字段 |
| 12 | 正常范围 | 两个数字输入框（最小值 - 最大值） | 为 Phase 3 结果校验 L2 预留；双空提交为 null |
| 13 | 过滤规则 | 多行文本 | 口径过滤条件，如 `status = 'PAID'`，会写入检索文档与提示词 |
| 14 | 生效数据源 | 单选"所有数据源"/"部分数据源" + 条件多选 | 选"部分数据源"时出现数据源多选框；决定召回时哪些数据源的问数能命中该指标 |
| 15 | 别名 | 动态列表，每行一个文本框，可"+ 添加"/删除 | 空串自动过滤；**重复报"别名不能重复"**；别名参与 BM25 召回 |
| 16 | 支持维度 | 多选下拉（可搜索） | 选项来自维度 Tab 维护的维度清单；仅启用状态的维度关联会进检索文档 |
| 17 | 依赖指标 | 动态列表：依赖指标下拉 + 计算表达式提示文本框 | 用于派生指标录入依赖（如"客单价"依赖"GMV"+"订单数"，提示 `GMV / 订单数`）；依赖下拉排除指标自身；**任何类型都可录入**（前端不强制） |

**级联规则（重点验证项，问题 2 修复内容）**：

1. 选择「表所属数据源」→ 自动清空 来源表/来源字段/时间字段 → 加载该数据源的表清单；
2. 选择「来源表」→ 自动清空 来源字段/时间字段 → 加载该表的字段清单；
3. 手输兜底：表/字段下拉均 `allow-create`，若手工输入的表不在已同步元数据中，字段候选为空但仍可手输；
4. 编辑恢复：打开编辑抽屉时按已保存的 source_ds_id/source_table 自动恢复下级候选，已存值不在候选中也正常回显。

**保存逻辑**：

- 前端校验：指标名称、指标定义必填；别名去重校验。
- 保存时自动过滤：空别名、未选依赖指标的依赖行。
- 新建后系统自动：写主表 → 同步别名/维度关系/依赖关系 → **重建检索文档（document_text）→ 异步补 embedding**。
- 编辑后系统自动：`version + 1` → 重建文档 → embedding 置空待重建补齐。

### 4.3 详情抽屉（只读）

点击列表行打开，600px 宽，展示：指标名称、别名、指标定义、业务域、**表所属数据源**、来源表、来源字段、时间字段、聚合方式、过滤规则、支持维度、生效数据源。

## 6. 问数链路行为（开关开时）

用户提问后，系统在生成 SQL 前执行指标召回，链路如下：

```text
用户问题
  → 选定数据源（既有逻辑，不动）
  → 指标召回 filter_metric_template   ← 新增（在术语召回之前）
      ├─ BM25：按指标名 + 别名打分（候选上限 2000）
      └─ 向量：按检索文档 document_text 相似度（阈值 0.4，Top 5）
      按 oid + 当前数据源过滤，仅 status=active 的指标参与
  → 术语召回 / SQL示例 / 自定义提示词（原逻辑，不动）
  → LLM 二次过滤 llm_filter_context    ← [指标] 分组排最前，LLM 按问题相关性保留
  → 组装提示词 init_messages            ← 指标块注入在术语块之前
  → 生成 SQL（原逻辑，完全不动）
```

**验证时可观察到的现象**：

1. **后端日志**出现 `FILTER_METRICS` 操作记录（operate='15'），`full_message` 为候选项列表；
2. **发送给 LLM 的提示词**（可从消息详情/日志查看）中，在术语块之前出现：

```text
以下是你可以参考的业务指标（请遵循其口径定义生成SQL）：

<metrics>
	<metric>
		<metric_name>GMV</metric_name>
		<metric_type>atomic</metric_type>
		<description>成交总金额</description>
		<aggregation>sum</aggregation>
		<filter_rule>status = 'PAID'</filter_rule>
		<time_field>pay_time</time_field>
		<unit>元</unit>
		<additivity>additive</additivity>
		<source_table>orders</source_table>
		<source_column>amount</source_column>
		<aliases>
			<alias>成交额</alias>
		</aliases>
		<dimensions>
			<dimension>
				<dimension_name>渠道</dimension_name>
				<default_column>channel</default_column>
			</dimension>
		</dimensions>
		<dependencies>
			<dependency>
				<depends_on_metric_name>订单数</depends_on_metric_name>
				<expression_hint>GMV / 订单数</expression_hint>
			</dependency>
		</dependencies>
	</metric>
</metrics>
```

3. 派生指标命中时，`dependencies` 中含依赖指标名与计算表达式提示，供 LLM 理解口径（MVP 阶段仅文档化展示，不做编译展开）；
4. 生成的 SQL 应体现指标口径（来源表/字段、聚合方式、过滤规则）。

**数据源隔离行为**：

- 指标 A 限定"部分数据源=[5]"：在数据源 5 的问数中可召回；数据源 6 的问数中不召回。
- 指标 A 限定数据源，但在**无数据源上下文**（全局助手）的问数中不参与 BM25/向量召回。
- "所有数据源"生效的指标在任何数据源下都可召回。

**关闭开关对照**：`METRIC_CENTER_ENABLED=false` 重启后，同样的问题提示词中**完全不出现**指标块与 `<metrics>` 标签，无 FILTER_METRICS 日志，回答行为与原版一致。

## 7. 元数据治理脚本（批量录入）

位置：`backend/scripts/metric_governance.py`。用于 LLM 辅助批量生成指标/维度/描述候选，**人工确认后导入**。在 `backend/` 目录下执行。

### 7.1 标准流程

```bash
cd backend

# 第 1 步：生成候选草稿（调用系统默认模型，逐表落盘，中断不丢已完成结果）
python scripts/metric_governance.py gen --ds 1

# 第 2 步：人工审阅并编辑草稿（可整行删除、修正任何字段）
#   编辑文件：governance_out/ds1/metrics.jsonl、dimensions.jsonl、comments.jsonl

# 第 3 步：先预览再导入
python scripts/metric_governance.py apply --ds 1 --dry-run
python scripts/metric_governance.py apply --ds 1

# 第 4 步（可选）：导入表/字段业务描述
python scripts/metric_governance.py apply-comments --ds 1
```

### 7.2 子命令参数

**gen（生成草稿）**：

| 参数 | 说明 |
| -- | -- |
| `--ds N` | 数据源 id（必填） |
| `--tables t1,t2` | 只处理指定表，默认该数据源全部已勾选表 |
| `--part all\|metrics\|docs` | 只生成指标部分或描述部分，默认 all |
| `--out DIR` | 输出目录，默认 `governance_out` |
| `--force` | 目标文件已存在时强制覆盖（默认跳过已存在分段防丢改动） |
| `--model-id` / `--api-base-url` 等 | 自定义模型，不传用系统默认模型 |
| `--oid N` | 工作空间 id，默认 1 |

**apply（导入指标/维度）**：

| 参数 | 说明 |
| -- | -- |
| `--ds N` | 数据源 id（导入的指标限定在该数据源生效） |
| `--dry-run` | 只预览将创建的维度/指标，不写库 |
| `--no-embedding` | 跳过 embedding 生成（之后可另行补齐） |

导入特性：幂等（同名维度/指标已存在则跳过）；维度先入库、指标后入库；依赖关系按指标名二次补齐；未加 `--no-embedding` 时会等待 embedding 线程完成。

**apply-comments（导入表/字段描述）**：

| 参数 | 说明 |
| -- | -- |
| `--overwrite` | 覆盖已有描述（默认**只补空白**） |

> 重要提示：`custom_comment` 写入后会进入**既有问数链路**的 DDL 描述，与 `METRIC_CENTER_ENABLED` 开关无关（属于人工治理动作，立即生效）。

## 8. 数据与检索规则说明

### 8.1 指标作用域与查重

- 指标唯一性：同一工作空间（oid）+ 数据源作用域内 `metric_name` 唯一。
- 作用域判定："所有数据源"的指标与"限定数据源"的指标可以同名共存；限定数据源间只要有 datasource_ids 交集即视为同作用域。
- 维度唯一性：oid 内 `dimension_name` 唯一。

### 8.2 召回过滤规则

| 场景 | 参与召回的指标 |
| -- | -- |
| 问数选定了数据源 ds | 所有"所有数据源"生效的 + 限定数据源包含 ds 的 + status=active |
| 问数无数据源（全局助手） | 仅"所有数据源"生效且 status=active 的指标 |
| 指标已停用（status=disabled） | 不参与任何召回 |

### 8.3 检索文档（document_text）

每次新建/编辑指标，系统自动重建该指标的检索文档，格式为逐行拼接：

```text
指标名称: GMV
指标定义: 成交总金额
业务域: 交易
别名: 成交额
指标类型: atomic
聚合方式: sum
过滤规则: status = 'PAID'
时间字段: pay_time
单位: 元
来源表: orders
来源字段: amount
支持维度: 渠道、平台
依赖指标: 订单数
```

（空字段自动省略行；"支持维度"仅含启用状态的关联。）向量检索基于该文档，口径变更后文档重建、embedding 置空并自动补齐。

### 8.4 版本与审计

- 每次编辑指标 `version + 1`；
- 增删改、启停全部有系统审计日志（模块 `metric`，操作类型 CREATE_OR_UPDATE/DELETE/UPDATE）；
- 问数侧召回日志 operate='15'（FILTER_METRICS），可按此关键字检索 chat_log。

## 9. 典型使用场景：节假日客流分析

> 场景来源：某单位"各处室节假日客流数据表"，含日期、节假日名称、节假日天数（假期内第几天，文本存储如"第三天"）、游客数量等字段。
> 典型业务问题：① 某节假日期间的游客总量；② 某节假日期间第几天的游客数量。
> 结论：当前 Phase 1 能力**可以覆盖**——两个场景本质是**同一个原子指标 + 不同过滤条件**，无需建两个指标；"节假日"和"第几天"配置为**维度**。

### 9.1 场景分析与配置原则

| 分析要点 | 结论 |
| -- | -- |
| 两个问题的关系 | 同一指标（对游客数量字段 sum），差别只在过滤条件：场景①加`节假日名称='春节'`；场景②再加`节假日天数='第三天'` |
| 指标建几个 | **1 个原子指标**。不要按节日拆指标（"春节游客量""国庆游客量"……）——节日是**维度取值**，不是指标 |
| 维度建哪些 | 必建"节假日"（映射节假日名称字段）+"节假日天数"（映射第几天字段）；若常问"按天趋势"可加"日期"维度；若表中还有处室字段且常被问到，应加"处室"维度 |
| 过滤规则字段填什么 | **留空**。哪个节日、第几天是随问题变化的条件，由 LLM 按问题动态添加；只有"恒定口径过滤"（如只统计正式数据）才写入过滤规则 |

### 9.2 指标配置（1 个原子指标）

| 字段 | 配置值 | 说明 |
| -- | -- | -- |
| 指标名称 | 节假日游客量 | 问数业务词的命中点 |
| 指标定义 | 各节假日、假期内各天的游客到访人数；按节假日过滤可统计整个假期总量，再加"第几天"过滤可统计单日人数 | **口径必须写清**：该表是"每日快照"还是"累计值"？各处室是分行存储还是一行汇总？sum 的语义取决于此，是最易出错的点 |
| 聚合方式 | sum | 假期总量=对该假期所有天 sum；单日=加过滤后 sum（多处室分行时自然汇总） |
| 过滤规则 | 留空 | 见 9.1 |
| 时间字段 | 日期字段 | 支持"1月28日到2月4日"这类按日期范围提问 |
| 指标类型 / 可加性 | 原子指标 / 可加 | 人次可加；若口径是去重人数则改"半可加"并在定义中说明 |
| 单位 | 人（或人次） | Phase 3 结果校验 L2 将使用 |
| 别名 | 客流量、游客数、客流 | 覆盖常见问法 |
| 来源表 / 来源字段 / 表所属数据源 | 按实际配置 | 用表单级联选择 |
| 生效数据源 | 按实际限定 | 多数据源场景下限定到客流库所在数据源 |
| 支持维度 | 勾选"节假日"、"节假日天数"（及可选"日期"） | 召回时随指标块注入提示词 |

### 9.3 维度配置

**维度 1：节假日**

| 字段 | 配置值 |
| -- | -- |
| 维度名称 | 节假日 |
| 默认字段 | 节假日名称字段（如 `holiday_name`） |
| 别名 | 假期、节日、假日 |
| 维度描述 | 节假日名称，取值如：春节、国庆节、五一劳动节等 |

**维度 2：节假日天数**（关键，取值域风险见 9.5）

| 字段 | 配置值 |
| -- | -- |
| 维度名称 | 节假日天数 |
| 默认字段 | 节假日天数字段（如 `holiday_day`） |
| 别名 | 第几天、第N天、假日第几天 |
| 维度描述 | 假期内第几天，**文本存储，取值为中文序数："第一天"、"第三天"……；该字段不支持排序** |

**维度 3（可选）：日期**

| 字段 | 配置值 |
| -- | -- |
| 维度名称 | 日期 |
| 默认字段 | 日期字段 |
| 维度描述 | 具体日期，用于按天趋势分析；仅做时间过滤时无需该维度（用指标的"时间字段"即可） |

### 9.4 两个场景的预期问数行为

**场景 A："春节假期游客总量"**

1. "游客"命中指标"节假日游客量"（BM25/向量），"节假日/假期"命中维度别名；
2. 提示词注入指标 XML：来源表、聚合 sum(游客数量字段)、维度"节假日→holiday_name"；
3. LLM 生成：`SELECT SUM(游客数量) FROM 表 WHERE 节假日名称='春节'`。

**场景 B："春节第三天的游客数量"**

1. 同样召回该指标；"第几天"命中维度 2 别名；
2. 维度描述中"取值为中文序数"帮助 LLM 写对取值；
3. LLM 生成：`SELECT SUM(游客数量) FROM 表 WHERE 节假日名称='春节' AND 节假日天数='第三天'`。

### 9.5 风险与注意点（当前能力边界）

1. **"第三天"是文本取值域，Phase 1 无取值治理**——若用户问"第3天""大年初三"，LLM 可能生成 `holiday_day='第3天'` 导致查不到数据。缓解：录入前统一库内取值为中文序数，并在维度描述中写明取值清单；**别名只能映射"字段名"的叫法，不能映射"值"**。
2. **趋势类问题排序会错**——"春节每天游客趋势"若 `ORDER BY 节假日天数`，文本排序"第十天"会排在"第二天"前。维度描述中已声明"不支持排序"；根治需库内加数字序号列（数据层调整，非本功能改造）。
3. **"期间总量"口径要人工定死**——若游客数量是"累计值"，sum 所有天会翻倍，必须在指标定义中写清楚并相应调整聚合/过滤方式。
4. **不要建节日专用指标**——见 9.1，指标爆炸会导致召回噪音与维护成本。
5. Phase 1 指标仅做**提示词注入**（文档化引导），不做编译期强约束，生成质量取决于 LLM + 口径描述的清晰度。

### 9.6 本场景验证要点

配置完成后按第 11.3 节执行问数验证，本场景补充两个专项检查：

| # | 步骤 | 预期 | 结论 |
| -- | -- | -- | -- |
| a | 提问"春节假期游客总量" | 召回"节假日游客量"；SQL 含 `WHERE 节假日名称='春节'` 且聚合为 sum | |
| b | 提问"春节第三天的游客数量" | SQL 同时含节假日名称与 `节假日天数='第三天'` 过滤 | |
| c | 错值问法"春节第3天游客数量"（专项风险测试） | 观察 LLM 是否被维度描述纠正为"第三天"；若未纠正，记录问题并考虑在维度描述中追加"第N天与中文序数的对应关系" | |

## 10. 排障指南

| 现象 | 排查点 |
| -- | -- |
| 问数提示词没有指标块 | ① `METRIC_CENTER_ENABLED=true` 且**已重启后端**；② 指标库非空且 status=启用；③ 指标生效数据源包含当前问数数据源；④ 指标名/别名/文档与问题相关（BM25+向量都有分数门槛） |
| 日志无 FILTER_METRICS | 同上 ①；异常时日志关键字 `filter_metric_template failed, keep metrics empty`（召回异常不阻断主流程，会静默降级为空） |
| 有候选但最终提示词仍无指标块 | LLM 二次过滤把全部候选判为不相关（日志关键字 `filter response parse failed` 时反而会保留全部候选）；候选总数 < 3 时会跳过二次过滤直接全保留 |
| 指标向量召不回 | `EMBEDDING_ENABLED=true`；`EMBEDDING_METRIC_SIMILARITY`（默认 0.4）过高可调低；embedding 是否补齐（document.embedding 非空）；embedding 模型服务是否可用 |
| 保存报"该指标在当前作用域已存在" | 名称（含 strip 后）在 oid + 数据源作用域内重复，改名或修改生效数据源 |
| 保存报"别名不能重复" | 前端校验，删除重复别名行 |
| 编辑表单来源表/字段下拉为空 | 该数据源未同步表元数据，或表为手输（不在元数据中）——属正常，允许手输兜底 |
| 维度列表"关联指标数"为 0 | 尚无指标关联该维度，或关联被禁用 |
| 管理页 403/被重定向 | 非空间管理员账号；用 ws_admin 账号登录 |
| 顶层菜单出现两个"指标管理" | 前端未重新构建或 `Menu.vue` 排除行丢失（问题 1，检查 `Menu.vue` 58-60 行 metric 排除项） |
| 级联（数据源→表→字段）不联动 | ① 后端是否已改代码并重启；② `source_ds_id` 列是否存在（alembic 是否到 m073metric0001）；③ 浏览器缓存，强刷页面 |
